Частые ошибки в dict-паттернах

Конспект обновлён 2026-06-06

Суть

Системные ошибки при работе с list[dict] — фильтрация, агрегация, сортировка, группировка.

Ошибки и как их исправить

1. Не определяю тип ответа до кода

Проблема: начинаю писать код не понимая что нужно вернуть.

Правило — перед каждой функцией спроси себя:

Что приходит на вход?
Что нужно получить? (число / список / словарь / один объект)
Как преобразовать?
Что вернуть?

2. Путаю count / sum / group by

Проблема: смешиваю три разные операции.

# count — сколько элементов
len([o for o in orders if o.get("status") == "paid"])

# sum — сумма значений
sum(o.get("total", 0) for o in orders if o.get("status") == "paid")

# group by — словарь по ключу
result = {}
for o in orders:
    key = o.get("status")
    result[key] = result.get(key, 0) + 1

3. Возвращаю не тот уровень данных

Проблема: нужен пользователь → возвращаю его total. Нужен один → возвращаю список.

Правило: перечитай условие и явно запиши тип ответа перед кодом.

# нужен: str (имя пользователя)
# не: int, не: list, не: tuple
def get_top_user(orders) -> str:
    ...

4. Ошибки в sorted / max / min

Проблема: путаю сортировку по ключу и по значению, sorted(dict) vs sorted(dict.items()).

d = {"Ivan": 100, "Anna": 200, "Petr": 50}

# ❌ sorted(d) — итерирует по ключам (строкам)
sorted(d, key=lambda x: x[1])  # x[1] — второй символ строки!

# ✅ sorted(d.items()) — итерирует по парам (ключ, значение)
sorted(d.items(), key=lambda x: x[1])  # x[1] — значение
sorted(d.items(), key=lambda x: x[1], reverse=True)  # по убыванию

# max по значению словаря
max(d, key=d.get)  # O(n) — быстрее чем sorted

5. Не проверяю пустые данные

Проблема: код ломается на пустом списке.

Чеклист защиты:

# пустой список
if not orders:
    return 0  # или [] или None

# отсутствие ключа
o.get("total", 0)  # всегда дефолт

# деление на ноль
avg = sum(vals) / len(vals) if vals else 0

# max/min без default
max(orders, key=lambda o: o.get("total", 0), default=None)

6. Variable shadowing — переопределение функций

Проблема: две функции с одним именем — вторая перезапишет первую.

# ❌ одно имя в двух местах
def get_expensive_paid(orders): ...  # задача 20
def get_expensive_paid(orders): ...  # задача 25 — перезапишет!

# ✅ разные имена
def get_max_paid_order(orders): ...
def get_max_paid_order_safe(orders): ...  # с защитой от пустых данных

7. Лишние проходы по данным

Проблема: считаю sum() несколько раз вместо сохранения результата.

# ❌ два прохода — sum считается дважды
"total_revenue": get_total_sum(orders),
"average_order_value": get_total_avg(orders),  # внутри снова sum()

# ✅ один проход — сохраняю в переменную
total = sum(o.get("total", 0) for o in orders)
avg = total / len(orders) if orders else 0

8. Слабая декомпозиция

Проблема: пишу всё в одной функции вместо маленьких.

Правило: одна функция = одна задача. Если функция делает два разных дела — раздели.

9. Не прохожу по коду руками

Проблема: считаю что код верный, не тестирую на граничных случаях.

Чеклист тестирования:

□ пустой список
□ один элемент
□ дубликаты
□ отсутствующий ключ
□ реальные данные

10. any() — уровень заказа, а не item

Проблема: в задаче big_orders (найти заказы где хотя бы один item дороже X) применяю any() не там.

# ❌ неверно — итерирую по items, а не по orders
result = [item for order in orders for item in order["items"] if item["price"] > 1000]

# ✅ верно — any() проверяет условие на уровне заказа
result = [
    order for order in orders
    if any(item["price"] > 1000 for item in order.get("items", []))
]

Правило: если задача звучит «найди заказы, где...» — итерирую по orders, условие — any(... for item in order["items"]). Если «найди товары, где...» — итерирую по items напрямую.

11. == True / == False вместо if value / if not value

Проблема: проверяю булево значение через сравнение, а это антипаттерн.

# ❌ работает только при строгом False
if player.get("premium") == False: ...

# ❌ если значение None — не сработает (None == False → False)
if movie.get("watched") == False: ...

# ✅ короче и работает для любых "falsy"
if not player.get("premium"): ...
if not movie.get("watched"): ...

# ✅ для положительной проверки
if player.get("premium"): ...

Правило: булево значение проверяем напрямую через if value / if not value. Сравнение через == нужно только если мы хотим строгий тип (но это почти никогда не нужно).

12. CamelCase вместо snake_case

Проблема: имена переменных в стиле JavaScript / Java.

# ❌ PEP 8 запрещает
sciFi_movies = [...]
sortRaitMovies = [...]

# ✅ snake_case — стандарт Python
sci_fi_movies = [...]
sorted_movies = [...]

Правило: переменные и функции — snake_case. Классы — PascalCase. Константы — UPPER_SNAKE_CASE. Это не вкусовщина, а PEP 8.

13. Лишний sorted() когда сортировка не нужна

Проблема: в задаче написано «порядок не важен», а я всё равно сортирую.

# ❌ задача: "порядок не важен" — лишняя работа
def watched_titles(movies):
    return sorted(m.get("title") for m in movies if m.get("watched"))

# ✅ читать задачу до конца
def watched_titles(movies):
    return [m["title"] for m in movies if m.get("watched")]

Правило: sorted() — это O(n log n). Перед каждым sorted() спроси: зачем он здесь? Если ответа нет — убрать.

Ключевые паттерны (запомнить)

# Подсчёт по группам
result = {}
for o in orders:
    key = o.get("status")
    result[key] = result.get(key, 0) + 1

# Сумма с фильтром
sum(o.get("total", 0) for o in orders if o.get("status") == "paid")

# Среднее с защитой
vals = [o.get("total", 0) for o in orders]
avg = sum(vals) / len(vals) if vals else 0

# Максимум по вычисленному полю
max(d, key=d.get)  # O(n) — лучше чем sorted

# Топ N
sorted(d.items(), key=lambda x: x[1], reverse=True)[:3]
