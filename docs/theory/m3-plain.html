Модуль 3 — Dict и агрегации на пальцах

Конспект обновлён 2026-09-14

Зачем эта заметка

Формальный конспект Модуля 3 — это таблицы с названиями паттернов. Названия запоминаются, а выбор между ними — нет. Здесь про выбор.

Весь модуль сводится к одному вопросу, который надо задавать перед каждой задачей:

Мне нужен один ответ на все данные — или свой ответ на каждую группу?

Один ответ на всё → никакого словаря не нужно. Ответ на каждую группу → нужен словарь. Почти все ошибки в этом модуле — это лишний словарь там, где хватило бы одной строки.

Образ: коробка чеков

Представь коробку с чеками из магазина. На каждом: имя покупателя, город, сумма, оплачен или нет.

Все задачи модуля — это вопросы к этой коробке. И они бывают ровно двух видов:

Вопросы про всю коробку целиком. «Сколько всего чеков?», «На какую сумму?», «Какие чеки больше тысячи?» — ты проходишь коробку один раз и получаешь одно число или один список. Словарь тут не нужен.

Вопросы про каждый город отдельно. «Сколько чеков в каждом городе?», «Сколько денег принёс каждый город?» — тебе нужно столько ответов, сколько городов. Заранее ты не знаешь ни сколько их, ни как они называются. Вот тут и нужен словарь: он растёт по мере того, как ты встречаешь новые города.

Это и есть граница между «просто цикл» и «цикл со словарём».

Пять паттернов, по одному примеру

COUNT — сколько штук

Вопрос ко всей коробке → одно число.

sum(1 for u in users if u.get("active"))

Читается буквально: «за каждого подходящего добавь единицу». Не len([...]) — тот сначала строит список в памяти, а он нам не нужен.

SUM — на какую сумму

То же самое, но добавляем не единицу, а поле.

sum(o.get("amount", 0) for o in orders if o.get("paid"))

0 вторым аргументом get — не формальность. Если у чека нет поля amount, без него будет None, и сложение упадёт.

FILTER — какие именно

Вопрос ко всей коробке → один список. Словарь не нужен.

[u for u in users if u.get("score", 0) > 80]

Часто вместе с сортировкой, и тогда важно не перепутать, что возвращаешь: объекты или только имена.

top = sorted(active, key=lambda x: x.get("score", 0), reverse=True)
return [u["name"] for u in top]        # список ИМЁН, а не словарей

GROUP BY — по каждой группе

А вот здесь словарь обязателен: ответов столько, сколько групп.

counts = {}
for u in users:
    city = u.get("city")
    counts[city] = counts.get(city, 0) + 1

Ключевая строка — counts.get(city, 0) + 1. Она означает: «возьми то, что уже накоплено для этого города, а если города ещё не встречали — начни с нуля». Без get с умолчанием первый же новый город даст KeyError.

Если в группу надо складывать не число, а список объектов, форма другая:

groups = {}
for w in words:
    key = len(w)
    groups.setdefault(key, []).append(w)

setdefault(key, []) — «дай список для этого ключа, а если ключа нет, заведи пустой». Это тот же приём, что get(key, 0), только для списков.

AVG — среднее по группе

Среднее нельзя накопить одной переменной: нужны и сумма, и количество. Поэтому всегда два словаря.

totals, counts = {}, {}
for a in athletes:
    key = a.get("sport")
    totals[key] = totals.get(key, 0) + a.get("score", 0)
    counts[key] = counts.get(key, 0) + 1
return {k: round(totals[k] / counts[k], 2) for k in totals}

Почему нельзя обойтись одним: чтобы усреднить, надо разделить накопленное на число слагаемых, а число слагаемых само нужно накапливать. Это самое частое место, где спотыкаются.

Работа с готовым словарём

Когда словарь уже построен, обычно нужны две вещи.

Кто максимальный. Возвращает ключ, а не значение:

max(d, key=d.get)        # "Moscow"

Читается так: «пройди по ключам, для сравнения бери d.get(ключ), верни сам ключ». Если написать просто max(d) — получишь ключ, наибольший по алфавиту, а не по значению. Это тихая ошибка: код работает, ответ неверный.

Топ-N. Сортировать надо пары, а не ключи:

top = sorted(d.items(), key=lambda x: x[1], reverse=True)[:3]
return [k for k, v in top]

d.items() даёт пары (ключ, значение), поэтому x[1] — это значение. Забыть .items() — записанная слабая точка: sorted(d) отсортирует ключи по алфавиту и молча выдаст не тот ответ.

Вложенность: цикл в цикле

Когда внутри каждого объекта лежит список других объектов (у заказа — товары, у студента — курсы), нужен двойной цикл:

for order in data:
    if order.get("status") == "paid":        # фильтр по ВНЕШНЕМУ
        for item in order.get("items", []):  # работа с ВНУТРЕННИМ
            total += item.get("price", 0)

Два места, где легко ошибиться:

  1. Фильтр не на том уровне. «Сумма товаров в оплаченных заказах» — оплачен заказ, значит проверка на внешнем цикле. Если поставить её внутрь, будешь проверять paid у товара, которого там нет.
  2. get("items", []) без умолчания. Если у заказа нет поля items, вернётся None, и внутренний for упадёт. Пустой список по умолчанию просто пропускает такой заказ.

Как выбрать за пять секунд

Что спрашивают Нужен ли словарь Что вернётся
сколько всего нет число
на какую сумму нет число
какие именно / отсортируй нет список
сколько в каждом… / по каждому… да словарь
среднее по каждому… да, два словарь
кто самый / топ-N сначала построй словарь ключ или список ключей

Слова-подсказки в условии: «в каждом», «по каждому», «для каждого» — это всегда группировка. Их отсутствие обычно значит, что словарь не нужен.

Частые ошибки

  • Словарь там, где ключ уникален. Если у каждого объекта свой неповторимый ключ, группировать нечего — нужен FILTER + SORTED, а не GROUP BY.
  • sorted(d) вместо sorted(d.items()) — сортировка по алфавиту вместо сортировки по значению.
  • Один словарь для среднего вместо двух.
  • get без умолчания — None вместо нуля, падение на сложении.
  • Возврат не того типа — список словарей там, где просили список имён.
  • Нет защиты перед max/min — на пустом списке они падают:
if not candidates:
    return None
return max(candidates, key=lambda x: x.get("score", 0))["name"]
