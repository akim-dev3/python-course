Модуль 1 — База Python на пальцах

Конспект обновлён 2026-09-14

Зачем эта заметка

Формальный конспект Модуля 1 перечисляет синтаксис. Синтаксис быстро вспоминается, а вот несколько вещей действительно сбивают даже тех, кто «всё это знает». Здесь только они.

Переменная — это ярлык, а не коробка

Привычный образ «переменная это коробка, в которую кладут значение» ломается ровно в одном месте — и оно потом больно стреляет.

В Python переменная это ярлык, наклеенный на объект. Присваивание не копирует объект, а переклеивает ярлык.

a = [1, 2, 3]
b = a           # НЕ копия: второй ярлык на тот же список
b.append(4)
print(a)        # [1, 2, 3, 4] — изменился и a

Для чисел и строк это незаметно, потому что их нельзя изменить — можно только создать новое значение и переклеить ярлык. А списки и словари изменяемы, и там разница видна сразу.

Если нужна настоящая копия:

b = a.copy()      # или a[:] для списка

Отсюда же вытекает главная ловушка функций — про неё ниже.

Условия: что считается «ложью»

В if можно писать не только сравнения. Питон сам приводит значение к «да/нет», и правило простое: пусто и ноль — это ложь, всё остальное — правда.

Ложь: 0, "", [], {}, (), None, False. Правда: любое непустое число, строка, список, словарь.

Поэтому вместо

if len(items) > 0:

пишут просто

if items:

Но здесь есть тонкость, из-за которой возникают тихие баги: 0 и None оба «ложь», хотя означают разное. Если поле может быть нулём по-настоящему, проверять надо явно:

if score is None:      # «значения нет»
if score == 0:         # «значение есть, и оно ноль»
if not score:          # это ОБА случая сразу — часто не то, что нужно

is против ==. == спрашивает «одинаковые ли значения», is — «это буквально один и тот же объект». Для None всегда пишут is None, потому что None в программе существует в единственном экземпляре.

Циклы: перебираешь элементы, а не индексы

Самая частая привычка из других языков — гонять счётчик и лазить по индексам:

for i in range(len(words)):     # так делать не надо
    print(words[i])

В Python перебирают сам список:

for word in words:
    print(word)

Индекс нужен редко. Если он действительно нужен вместе со значением — есть enumerate:

for i, word in enumerate(words):
    print(i, word)

А если надо идти по двум спискам параллельно — zip:

for name, score in zip(names, scores):
    ...

break и continue. break выходит из цикла совсем, continue пропускает текущий шаг и идёт к следующему. Путаница между ними даёт результат, который выглядит почти правильным, — самый неприятный вид ошибки.

Опасность изменять список во время перебора. Если удалять элементы из того же списка, по которому идёшь, часть элементов будет пропущена — итератор сдвигается. Правильно — собрать новый список:

items = [x for x in items if not надо_удалить(x)]

Функции: две настоящие ловушки

Синтаксис функции тривиален. Ловушек ровно две, но обе злые.

return внутри цикла обрывает всю функцию

def has_even(nums):
    for n in nums:
        if n % 2 == 0:
            return True     # выходим из ФУНКЦИИ, не из цикла
    return False            # сюда дойдём, только если ни одного не нашли

Это не баг, а приём: как только ответ найден, дальше искать незачем. Но если по ошибке поставить return не там, функция вернётся после первого же элемента.

Особенно важно, где стоит финальный return. Внутри цикла на том же уровне, что и if, — функция всегда завершится на первом элементе и остальные не проверит.

Изменяемый аргумент по умолчанию

def add(item, target=[]):     # ТАК НЕЛЬЗЯ
    target.append(item)
    return target

Список в умолчании создаётся один раз при определении функции, а не при каждом вызове. Поэтому он накапливает значения между вызовами:

add(1)   # [1]
add(2)   # [1, 2] — сюрприз

Правильно:

def add(item, target=None):
    if target is None:
        target = []
    target.append(item)
    return target

Функция без return возвращает None

Если забыть return, функция вернёт None — и упадёт не здесь, а там, где результатом попробуют воспользоваться. Отладить это неприятно, потому что ошибка вылезает далеко от причины.

Строки: неизменяемы

Строку нельзя поменять на месте — любая операция создаёт новую.

s = "hello"
s.upper()          # вернуло "HELLO", но s не изменилась
s = s.upper()      # вот теперь изменилась

Забытое присваивание — очень частая ошибка: код работает, ничего не падает, результат прежний.

Полезный минимум:

s.lower() / s.upper()        # регистр
s.strip()                    # убрать пробелы по краям
s.split()                    # разбить по пробелам → список слов
",".join(words)              # склеить список в строку
s.replace("a", "b")
s[::-1]                      # развернуть
"abc" in s                   # есть ли подстрока
s.isalnum()                  # только буквы и цифры?
f"Привет, {name}!"           # подстановка значений

split() без аргументов удобнее, чем split(" "): он схлопывает несколько пробелов подряд и игнорирует пробелы по краям.

Частые ошибки

  • b = a для списка вместо b = a.copy() — меняешь один, «сам собой» меняется второй
  • if not x там, где нужно if x is None — ноль ошибочно считается отсутствием
  • for i in range(len(...)) вместо перебора элементов
  • удаление из списка прямо во время цикла по нему
  • s.upper() без присваивания результата
  • изменяемый аргумент по умолчанию (=[], ={})
  • забытый return → None и падение в другом месте
