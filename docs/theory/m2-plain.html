Модуль 2 — Коллекции на пальцах

Конспект обновлён 2026-09-14

Зачем эта заметка

Формальный конспект перечисляет методы списка. Методы гуглятся за секунду. Что не гуглится — это какую коллекцию брать и почему выбор влияет не на стиль, а на скорость работы в тысячи раз.

Три коллекции — три разных вопроса

Коллекция Отвечает на вопрос Порядок Дубликаты
list «дай мне элемент номер N» важен можно
set «а такое вообще было?» не важен схлопываются
tuple «это одна неделимая запись» важен можно

Выбор делается по вопросу, который ты будешь задавать чаще всего.

Список — упорядоченная лента

Список хранит элементы подряд, поэтому доступ по номеру мгновенный, а вот поиск по значению — перебор.

lst[0]          # мгновенно
x in lst        # перебирает ВСЕ элементы, пока не найдёт
lst.pop()       # с конца — мгновенно
lst.pop(0)      # с начала — сдвигает весь список, дорого

Последняя строка — ловушка, которая всплывёт ещё раз в Модуле 6, когда будешь делать очередь.

Срезы. lst[начало:конец], конец не включается.

lst[:3]      # первые три
lst[-3:]     # последние три
lst[::-1]    # копия задом наперёд
lst[:]       # полная копия — вот так копируют список

Сортировка — два разных инструмента, и их путают:

lst.sort()            # меняет сам список, возвращает None
new = sorted(lst)     # НЕ трогает исходный, возвращает новый

Классическая ошибка: lst = lst.sort() — список превращается в None, потому что sort() ничего не возвращает.

Множество — мгновенная проверка «было или нет»

Множество не хранит порядок и не хранит дубликаты. Взамен даёт то, ради чего его и берут: проверка принадлежности не зависит от размера.

x in some_list    # чем длиннее список, тем дольше
x in some_set     # одинаково быстро при любом размере

Разница не «чуть быстрее». На списке из 100 000 элементов проверка может перебрать все 100 000; множество ответит за одно действие. Именно на этом строится половина оптимизаций в Модуле 4.

Отсюда типовой приём «видели ли мы это раньше»:

seen = set()
for x in items:
    if x in seen:
        return x          # первый повтор
    seen.add(x)

И операции над множествами вместо вложенных циклов:

set(a) & set(b)     # что есть в обоих
set(a) | set(b)     # всё вместе, без повторов
set(a) - set(b)     # что есть в a, но нет в b

Чего множество не умеет: хранить порядок и хранить изменяемые элементы. set из списков собрать нельзя — только из чисел, строк, кортежей.

Убрать дубликаты с сохранением порядка одним set(...) не получится — порядок потеряется. Нужен приём с двумя структурами:

seen, result = set(), []
for x in items:
    if x not in seen:
        seen.add(x)
        result.append(x)

Здесь set работает как быстрый «список того, что уже видели», а порядок держит обычный список.

Кортеж — запись, а не коллекция

Кортеж выглядит как список, который нельзя менять, но смысл у него другой. Список — это «много однотипных штук». Кортеж — это одна вещь из нескольких частей: координата (x, y), пара (имя, счёт), строка таблицы.

Практическая польза в двух местах.

Распаковка — читается лучше, чем обращение по индексу:

for name, score in pairs:
    ...
first, *rest = items       # первый отдельно, остальные списком

Кортеж можно положить в множество или сделать ключом словаря, а список — нельзя, потому что список изменяем.

Comprehension — цикл, свёрнутый в строку

Это не «красивее», а стандартный способ записи для трёх типовых действий.

[x * 2 for x in nums]                 # преобразовать каждый
[x for x in nums if x > 0]            # отобрать
[x * 2 for x in nums if x > 0]        # отобрать и преобразовать

Порядок частей всегда один: что вернуть → откуда взять → при каком условии.

Работает и для других типов:

{x for x in nums}                     # множество
{u["name"]: u["age"] for u in users}  # словарь
sum(1 for x in nums if x > 0)         # генератор: считает, не строя список

Последняя строка важна: круглые скобки вместо квадратных дают генератор — он не создаёт список в памяти, а выдаёт значения по одному. Для sum, max, any, all это то, что нужно.

Когда не надо. Если внутрь просятся два вложенных цикла и условие — обычный for будет понятнее. Comprehension хорош, пока помещается в одну строку и читается слева направо.

Частые ошибки

  • lst = lst.sort() → список становится None
  • x in list в цикле там, где нужен set — превращает O(n) в O(n²)
  • set(items) для удаления дубликатов, когда порядок важен
  • попытка положить список в set или сделать его ключом словаря
  • b = a вместо b = a[:] — второй ярлык на тот же список
  • pop(0) в цикле — незаметно дорогая операция

Вопросы для самопроверки

  2. Чем lst.sort() отличается от sorted(lst)?
  3. Как убрать дубликаты, сохранив порядок, и почему одного set мало?
  4. Почему список нельзя сделать ключом словаря, а кортеж можно?
  5. Чем отличается [x for x in nums] от (x for x in nums) и когда нужен второй?
