# Python-курс

Личный курс Python: drill-задачи с автопроверкой и конспекты. Всё решается
и проверяется прямо в браузере — Python исполняется на стороне клиента
через [Pyodide](https://pyodide.org/) (CPython, скомпилированный в WebAssembly),
никакого сервера нет.

**Сайт:** https://akim-dev3.github.io/python-course/

## Как это устроено

Источник правды — обычные `.py`-файлы в `drills/`. Сайт не дублирует их,
а собирается из них скриптом: задачи, условия и проверки вытаскиваются
из кода и комментариев.

```
drills/**/*.py  ──build_content.py──>  docs/content.json  ──>  сайт
конспекты .md   ──build_theory.py───>  docs/theory/*.html
```

Проверки в задачах записаны функцией `check(actual, expected, label)`, которая
уже лежит в самих файлах. В браузере она подменяется версией, возвращающей
структурированный результат, — поэтому сайт показывает «ожидалось X,
получилось Y» по каждой проверке, а не разбирает текстовый вывод.

Файл режется на неизменяемые куски и «слоты» под решения, причём склейка
кусков обязана побайтово совпасть с оригиналом — это проверяется на сборке.
Благодаря этому кнопка «скачать» отдаёт файл ровно того же формата: его можно
положить обратно в репозиторий и запустить локально.

## Локально

```bash
# прогнать любой drill напрямую — печатает OK/FAIL по каждой проверке
python drills/06_data_structures/p1_stack.py

# пересобрать сайт (нужен пакет markdown)
python build_content.py --verify --lint

# открыть сайт локально: file:// не подойдёт, нужен http
python -m http.server 8000 --directory docs
```

Флаги сборки:

- `--verify` — проверить, что каждый файл побайтово восстанавливается из
  сегментов. Без этого гейта выгрузка решений может незаметно испортить формат.
- `--lint` — проверить, что в публикуемое не утекли личные данные.

Тесты механики проверок, без браузера:

```bash
python tests/test_runner_local.py
```

## Структура

```
drills/          задачи по модулям — источник правды
patterns/        шпаргалки
projects/        мини-проекты
docs/            публикуемый сайт (GitHub Pages отдаёт эту папку)
  runner.py      исполнение задач и переопределённый check()
  build_*.py     генераторы (в корне)
tests/
```

## Прогресс и решения

Быстрый слой — `localStorage` браузера. Долговременное хранилище — сам
репозиторий: кнопка «Синхронизация» кладёт прогресс в `docs/progress.json`,
и он доступен с любого устройства.

Для записи нужен **fine-grained** токен, выданный **на один этот репозиторий**
с правом `Contents: read and write` и со сроком годности. Токен хранится
в localStorage браузера, а страница публичная, поэтому классический токен
с полным доступом сюда вставлять нельзя: у fine-grained худший сценарий
ограничен этим репозиторием.

Слияние идёт **позадачно по времени правки** — работа с двух устройств
не затирается целиком.

Есть также «Записать решения в файлы курса» — она коммитит собранные `.py`
прямо в репозиторий. После этого локально нужен `git pull`.

Автономные варианты без токена никуда не делись: «скачать файл»,
«скачать всё (.zip)», «экспорт/импорт» прогресса.
